# MegaShorts 플랫폼 종합 아키텍처 및 해설 문서

이 문서는 MegaShorts 플랫폼의 전체적인 기술 구조, 인증 프로세스, 인프라 전략 등을 기록하는 마스터 문서입니다. 시스템이 확장됨에 따라 지속적으로 업데이트됩니다.

## 1. 영상 재생 및 권한 확인 프로세스 (Video Playback & Authorization)

유저가 컨텐츠를 클릭하여 영상 스트리밍이 시작되기까지의 권한 검증은 보안을 위해 **프론트엔드(빠른 UI)와 백엔드(엄격한 검증)의 투트랙(Two-track)**으로 이루어집니다.

### 1-1. 프로세스 흐름도
1. **초기 로드 (프론트엔드)**: 
   - 유저가 로그인할 때, 서버로부터 "구독 상태"와 "코인으로 영구 소장한 비디오 ID 목록"을 가져와 브라우저 메모리(React Query Cache)에 저장합니다.
2. **시청 시도 (UI 검증)**:
   - 유저가 특정 에피소드로 넘길 때, 프론트엔드의 `PlayPermissionCheck`가 메모리에 저장된 "소장 목록"이나 "구독 상태"를 확인합니다.
   - 권한이 있다면 API 통신(딜레이) 없이 즉시 플레이어를 화면에 렌더링합니다. (0초 지연)
3. **실제 영상 스트리밍 요청 (보안 검증)**:
   - 플레이어가 렌더링되어 Cloudflare Stream에 실제 영상 데이터를 요청할 때, 시스템은 백엔드에 **'보안 스트리밍 토큰(Signed Token)'**을 요청합니다.
   - 이때 백엔드(Next.js API)가 DB를 직접 조회하여 유저의 실제 코인 소장 여부나 구독 상태를 "최종적으로 한 번 더" 엄격하게 검증합니다.
   - 검증이 통과되어야만 1회용 토큰이 발급되고 실제 영상 데이터(.m3u8, .ts)가 디바이스로 전송됩니다.

### 1-2. 로컬 데이터 조작 시나리오
- **질문**: "유저가 로컬 데이터를 조작해서 '코인 결제함' 상태로 만들면 공짜로 보는 것 아닌가요?"
- **답변**: 불가능합니다. 유저가 로컬 데이터를 조작하면 2번(UI 검증)을 통과해서 검은색 영상 플레이어 화면까지는 띄울 수 있습니다. 하지만 3번(실제 영상 요청) 단계에서 백엔드 DB에 구매 기록이 없기 때문에 토큰 발급이 거절되며, 결국 영상은 무한 로딩되거나 403 에러가 발생하여 재생되지 않습니다. 로컬 저장은 오직 "정상 유저가 기다림 없이 영상을 보게 해주는 최적화 장치"일 뿐입니다.

## 2. 인프라 및 글로벌 분산 캐시 전략

### 2-1. 단일 소스 오브 트루스 (SSOT)
- 메인 데이터베이스: **Supabase PostgreSQL (한국 서울 AWS 리전)**
- 모든 결제, 유저 권한, 소장 기록의 최종 원본은 반드시 이곳에 저장됩니다.

### 2-2. 캐싱 전략: 구독은 KV, 코인은 브라우저 캐시 (투트랙)
글로벌 속도 최적화와 데이터 무결성을 위해 데이터의 특성에 따라 캐시 전략을 완벽히 분리합니다.

**A. 코인 및 소장 영상 이력 (Supabase DB + React Query 브라우저 캐시)**
- 코인 차감 및 영상 소장은 글로벌 전파가 불필요하며, **유저 본인만 즉각적으로 확인**하면 됩니다.
- 유저가 로그인할 때 서울의 DB에서 전체 소장 목록을 한 번에 가져와 브라우저 로컬(React Query)에 저장합니다.
- 이후 스와이프할 때마다 브라우저 로컬 캐시를 읽으므로 **지연시간이 0초**입니다. 굳이 이 데이터를 글로벌 KV에 올리고 동기화를 기다리는 복잡한 작업(오버엔지니어링)을 하지 않습니다.

**B. 구독 상태 (Cloudflare KV 글로벌 캐시)**
- 구독 상태(`isSubscribed: true`)는 한 번 업데이트되면 한 달간 변하지 않는 정적 데이터에 가깝지만, 플랫폼을 켤 때마다 무조건 조회해야 하는 핵심 값입니다.
- 미국 유저가 앱을 열 때마다 구독 여부를 확인하러 태평양을 건너 서울 DB를 다녀오면 전체 앱 로딩이 느려집니다.
- 따라서 구독 상태만 **Cloudflare KV**에 복제해 둡니다. 전 세계 엣지 노드에 데이터가 쫙 깔리므로, 미국 유저는 버지니아 노드에서 10ms 만에 구독 상태를 확인하고 즉시 앱 진입이 가능합니다.

## 3. 다국어 (i18n) 및 SEO 전략

### 3-1. 언어 정책
- **기본 언어 (Default)**: **영어 (English)**
- **확장 언어**: 중국어 (Chinese) - *추후 단일 소스 파일에 언어셋만 추가하여 무한 확장 가능*

### 3-2. 구글 SEO 표준 라우팅 정책
- 구글 검색 엔진 최적화(SEO)를 위해 **URL Prefix(경로 기반) 라우팅**을 사용합니다.
- 단, 기본 언어(영어)는 URL에 prefix를 붙이지 않아 URL 깊이를 최소화합니다.
  - **영어(기본)**: `megashorts.com/videos`
  - **중국어**: `megashorts.com/zh/videos`
- 이렇게 하면 `next-intl`의 `localePrefix: 'as-needed'` 설정에 의해 기본 URL의 검색 노출 순위가 완벽히 보존됩니다.

## 4. 프론트엔드 및 플랫폼 UI 구조

- **코어 스택**: Next.js 15 (App Router), React, TypeScript
- **스타일링**: Tailwind CSS, Shadcn UI (Radix 기반)
- **비디오 플레이어**: Cloudflare Stream + Swiper.js를 활용한 세로형 틱톡 스타일 무한 스크롤 인터페이스.
- **PWA (Progressive Web App)**: 
  - 유저 첫 방문 시 거슬리지 않는 하단 스낵바 형태로 "앱 설치"를 권유.
  - 설치 시 브라우저 UI(주소창)가 사라지고 세로 화면(Portrait)으로 고정되어 완벽한 네이티브 앱 경험 제공.
  - 서비스 워커를 통한 HLS 영상 세그먼트 백그라운드 사전 다운로드(Pre-fetching)로 로딩 없는 스와이프 구현.

## 5. 결제 및 정산 아키텍처 (Stripe 도입)

- 기존 하드코딩된 한국 전용 결제(토스)를 걷어내고 글로벌 표준인 **Stripe**로 일원화합니다.
- **다통화(Multi-currency) 정책**: Stripe의 자동 환전 기능을 활용하여 한국인에게는 원화(₩), 타국가에는 현지 통화로 가격을 보여주고 결제받아 환전 수수료에 대한 유저 거부감을 없애고 구매 전환율을 극대화합니다.
- **가격 연동**: 결제 모달에 표시되는 요금은 하드코딩이 아닌, DB(`SystemSettings`)에서 관리자가 설정한 가격을 동적으로 불러와 렌더링합니다.
